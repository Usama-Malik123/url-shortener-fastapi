# CLAUDE.md

## Project

A production-style FastAPI URL shortener — the app layer of a larger DevOps portfolio (this
codebase is later deployed via Terraform/ECS, then Kubernetes/ArgoCD, then monitored with
Prometheus/Grafana). Keep it simple and readable: this is a reference implementation, not a
feature-complete product. No auth, no rate limiting — intentionally absent, not missing by
accident.

## Tech stack

FastAPI, SQLAlchemy 2.0, Alembic, Postgres, Redis, Pydantic v2 + pydantic-settings,
prometheus-fastapi-instrumentator, pytest, ruff, Docker / docker-compose.

## Module layout

```
app/
  main.py          FastAPI app instance, all route handlers
  config.py         pydantic-settings Settings — the only source of config (env vars)
  db.py             SQLAlchemy engine, SessionLocal, Base, get_db dependency
  redis_client.py   Redis connection pool + get_redis dependency
  models.py         SQLAlchemy ORM models
  schemas.py        Pydantic request/response schemas
  crud.py           DB access functions
  shortcode.py      short-code generation
```

Flat, one concern per file — no service/repository/interface layers. Keep it that way unless
the app genuinely outgrows it.

## Conventions

- **Config**: env vars only, read through `app/config.py::settings`. Never hardcode connection
  strings or read `os.environ` directly elsewhere.
- **Schema changes**: edit `app/models.py`, then run
  `alembic revision --autogenerate -m "..."`, review the generated migration file by hand, run
  `alembic upgrade head` locally to verify, commit the migration alongside the model change.
  Migrations are never auto-run on container start — always an explicit step (see README).
- **Adding an endpoint**: add the handler to `app/main.py` (split into routers only if this
  file grows past ~5-6 endpoints), add/extend schemas in `schemas.py`, add DB access in
  `crud.py` if needed. Route order matters — fixed paths (`/health`, `/metrics`) must be
  registered before the catch-all `GET /{code}`.
- **Testing**: tests run against real Postgres and Redis (docker-compose locally, service
  containers in CI) — no SQLite/fakeredis mocking. One test file per feature area in `tests/`.
  Plain `pytest` + sync `TestClient`, no `pytest-asyncio`.
- **Lint**: `ruff check .` (config in `ruff.toml`; `alembic/versions/` is excluded since those
  files are autogenerated).
- **Dependencies**: plain pinned `requirements.txt` (runtime) and `requirements-dev.txt` (dev
  tools, includes `-r requirements.txt`). No pyproject.toml/uv/poetry.
